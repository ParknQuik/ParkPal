# ParkPal Agent Knowledge Index

This directory defines the repo-local knowledge index used by ParkPal agents and
developers. Markdown remains the human source of truth; the generated SQLite
database is only a fast retrieval layer.

## Commands

```bash
npm run knowledge:build
npm run knowledge:query -- "mobile header dark mode"
npm run knowledge:query -- "current project status" --json
npm run knowledge:validate
```

For test and debugging work only, both build and query scripts support a
`KNOWLEDGE_DB_PATH` override:

```bash
KNOWLEDGE_DB_PATH=/tmp/parkpal-knowledge.db npm run knowledge:build
KNOWLEDGE_DB_PATH=/tmp/parkpal-knowledge.db npm run knowledge:query -- "current project status" --json
```

Normal agent and developer workflows should use the default generated database
under the local OS temp directory. The path is scoped by a hash of the repo root
so multiple checkouts do not share an index.

## Files

- `sources.json` lists the deliberately indexed markdown sources.
- `schema.md` documents the chunk model and SQLite tables.
- `knowledge.db` is generated by `npm run knowledge:build` outside the tracked
  source tree unless `KNOWLEDGE_DB_PATH` is set.

## Rules

- Add sources deliberately instead of indexing every markdown file.
- Treat `needs-verification`, `planned`, and `historical` results as leads.
- Verify current status with git, `STATUS_REPORT.md`, and source files before
  making implementation claims.

## Freshness

`knowledge:build` records the HEAD commit plus a hash and mtime for each indexed
source file. `knowledge:query` compares that stored metadata with the current
workspace.

If HEAD moved or an indexed source changed, text output prints a short
`Freshness warnings` block and `--json` includes a `warnings` array. Warnings do
not make the query unusable; they mean the index should be treated as routing
metadata until `npm run knowledge:build` is run again.

Chunks may also be labeled with `detectedDate`, `isStale`, and `staleReason`.
Current-status queries boost `STATUS_REPORT.md` and the beta checklist above old
roadmap sections, while stale or historical chunks are retained for discovery
and history-oriented searches.

## Validation

`npm run knowledge:validate` builds temporary SQLite databases and leaves the
default ignored database untouched. It covers:

- fresh-index queries with no warnings
- simulated source-hash drift producing `source-changed`
- simulated HEAD drift producing `head-changed`
- current status and beta checklist ranking ahead of stale roadmap next steps
- historical roadmap labels for old launch/next-step sections
- `needs-verification` routing for deployment status
- `.json` and `.tsx` reference extraction without truncated extensions
