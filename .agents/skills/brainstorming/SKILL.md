# Brainstorming

Use this when a request leaves meaningful product or design choices unresolved. Start by checking relevant project context and existing conventions. Ask only about choices whose answers would materially change the design; infer routine details from the project and user request.

For open-ended work, outline a small number of viable approaches with the main trade-offs and a recommendation. Present a concise design covering the relevant components, behavior, data flow, failure handling, and verification. Keep the discussion proportional to the task and follow the active collaboration mode: continue implementation when requested, or stop at a plan when that is the requested outcome.

Do not require repeated approval checkpoints for each design section. Do not create or commit a design document unless the user requests that artifact. Do not refer to unavailable skills or tools; use available project planning guidance when a plan is needed. Follow repository and session approval rules for commits, pushes, deployments, and other external or costly actions.

Keep the solution focused on the requested outcome. Revisit assumptions when new evidence or user direction changes the design.
